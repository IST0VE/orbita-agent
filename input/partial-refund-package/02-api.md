# 02. Контракт API: частичный возврат

Контракт REST для orders-api. Реализует требования ФТ-1, ФТ-2, ФТ-3, ФТ-5,
ФТ-6 и ФТ-9; ограничение по числу операций из НФТ-1 проверяется на входе.

## Endpoints

### Создать возврат

```
POST /orders/{order_id}/refunds
```

Заголовок `Idempotency-Key` обязателен — это ключ из ФТ-6. Запрос без него
отклоняется.

Тело запроса:

```json
{
  "item_ids": ["itm-1", "itm-3"],
  "reason": "customer_request",
  "comment": "не подошёл размер"
}
```

Ответ 201:

```json
{
  "refund_id": "rfn-90114",
  "order_id": "ord-10231",
  "status": "pending",
  "amount": "1350.00",
  "currency": "RUB",
  "item_ids": ["itm-1", "itm-3"],
  "created_at": "2026-09-01T10:14:00Z",
}
```

Коды ответов:

- `201` — возврат создан, отправлен эквайеру;
- `400` — пустой `item_ids`, неизвестный `item_id`, отсутствует
  `Idempotency-Key`;
- `404` — заказа нет;
- `409` — заказ не в статусе `delivered`; позиция уже возвращена; исчерпан
  лимит операций по платежу;
- `422` — сумма возврата после применения скидки равна нулю;
- `502` — эквайер не ответил; возврат создан в статусе `pending`, повторять
  запрос с тем же ключом безопасно.

### Прочитать возврат

```
GET /orders/{order_id}/refunds/{refund_id}
```

Ответ 200 — тот же объект возврата, что и при создании, с актуальным статусом
из `pending`, `settled`, `rejected`, `cancelled`.

### Отменить возврат

```
DELETE /orders/{order_id}/refunds/{refund_id}
```

Отменяет возврат в статусе `pending`. Ответ `204`. Для терминальных статусов
— `409`.

## Модель ошибки

Единая для всех ответов 4xx и 5xx:

```json
{
  "error": {
    "code": "item_already_refunded",
    "message": "Позиции itm-1 уже возвращены возвратом rfn-90101",
    "details": {"item_ids": ["itm-1"], "refund_id": "rfn-90101"}
  }
}
```

Коды ошибок: `order_not_found`, `order_status_not_allowed`,
`item_already_refunded`, `refund_limit_reached`, `zero_amount`,
`idempotency_key_missing`, `idempotency_key_conflict`, `acquirer_unavailable`,
`delivery_recall_failed`.

## Идемпотентность

Ключ передаётся заголовком `Idempotency-Key`, живёт **24 часа** и хранится
вместе с телом ответа первой операции. Повтор с тем же ключом и тем же телом
отдаёт `201` и тот же `refund_id`. Повтор с тем же ключом и другим телом —
`409` с кодом `idempotency_key_conflict`.

## Поведение по статусам заказа

| Статус заказа | Создание возврата |
|---|---|
| `created` | `409`, денег нет |
| `paid` | разрешено |
| `shipped` | разрешено, с проверкой снятия с доставки |
| `delivered` | разрешено |
| `partially_refunded` | разрешено, пока есть невозвращённые позиции |
| `refunded` | `409`, возвращать нечего |
| `cancelled` | `409` |

## Результат долгой операции

Подтверждение эквайера асинхронное. Клиент API узнаёт результат опросом
`GET /orders/{order_id}/refunds/{refund_id}` или из события
`refund.settled` — см. документ 03.

Опрос: не чаще одного раза в 5 секунд, ожидаемое время подтверждения —
до 60 секунд, предельное — TBD, зависит от эквайера.

## Пагинация

Коллекция возвратов по заказу не пагинируется: их не больше 20 по НФТ-1.

## Версионирование

Ломающие изменения — через новый префикс `/v2`. Добавление необязательного
поля в ответ ломающим не считается.
