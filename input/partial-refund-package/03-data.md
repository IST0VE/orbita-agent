# 03. Данные и события: частичный возврат

## Сущности

### Refund

Операция возврата. Одна запись — одно обращение к эквайеру.

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `refund_id` | string | да | `rfn-` + номер |
| `order_id` | string | да | заказ |
| `payment_id` | string | да | платёж, по которому идёт возврат |
| `amount` | decimal(12,2) | да | сумма с учётом скидки по ФТ-3 |
| `currency` | char(3) | да | всегда валюта платежа |
| `status` | enum | да | `pending`, `settled`, `rejected`, `cancelled` |
| `idempotency_key` | string | да | ключ из ФТ-6, уникален в пределах заказа |
| `acquirer_ref` | string | нет | идентификатор операции у эквайера |
| `reason` | enum | да | `customer_request`, `defect`, `not_delivered` |
| `created_at` | timestamptz | да | |
| `settled_at` | timestamptz | нет | |

Индексы: `(order_id, status)`, уникальный `(order_id, idempotency_key)`.

### RefundItem

Позиция внутри возврата. Связывает возврат с позициями заказа и не даёт
вернуть одну позицию дважды — это ФТ-5.

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `refund_id` | string | да | |
| `item_id` | string | да | позиция заказа |
| `amount` | decimal(12,2) | да | доля суммы возврата на эту позицию |

Уникальный индекс `(item_id)` в пределах заказа: позиция может входить не
более чем в один **нетерминальный или успешный** возврат. Отменённые и
отклонённые возвраты освобождают позицию.

### Order (изменения)

Добавляется статус `partially_refunded`. Добавляется вычисляемое поле
`refunded_amount` — сумма `settled` возвратов по заказу. Хранение суммы
отдельным полем нужно для ФТ-4: остаток от округления считается по ней.

## Хранение

Возвраты живут в базе orders-api, в отдельных таблицах `refunds` и
`refund_items`. Срок хранения — по НФТ-3, не менее 5 лет; удаления нет,
архивация TBD.

## События

Публикуются в существующий топик `orders.events`, ключ партиционирования —
`order_id`, чтобы события одного заказа не переставлялись местами.

| Событие | Когда | Producer |
|---|---|---|
| `refund.created` | возврат создан и отправлен эквайеру | orders-api |
| `refund.settled` | эквайер подтвердил | orders-api |
| `refund.rejected` | эквайер отказал | orders-api |
| `order.partially_refunded` | заказ перешёл в `partially_refunded` | orders-api |
| `order.refunded` | возвращены все позиции | orders-api |

Тело `refund.settled`:

```json
{
  "event": "refund.settled",
  "refund_id": "rfn-90114",
  "order_id": "ord-10231",
  "payment_id": "pay-77341",
  "amount": "1350.00",
  "item_ids": ["itm-1", "itm-3"],
  "occurred_at": "2026-09-01T10:14:31Z"
}
```

Потребители: сервис уведомлений (письмо клиенту), витрина аналитики,
интеграция с 1С.

## Миграции

1. Создать `refunds` и `refund_items`.
2. Добавить `partially_refunded` в enum статусов заказа.
3. Заполнить `refunded_amount` по историческим полным возвратам одним
   пересчётом.

Откат: обратная миграция удаляет таблицы. Значение `partially_refunded` из
enum не удаляется — на исторические заказы оно не проставлялось, но снятие
значения из enum в PostgreSQL требует пересоздания типа.

## Целостность

- сумма `amount` по `refund_items` одного возврата равна `amount` возврата;
- сумма `settled` возвратов по заказу не превышает оплаченной суммы —
  проверяется на запись, а не только в коде;
- возврат по заказу без платежа невозможен: внешний ключ на `payment_id`.
