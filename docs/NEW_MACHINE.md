# Развёртывание на новой машине

[Документация](README.md) / Новая машина

**Для кого:** на машине есть только Docker, а Orbita нужно поднять с нуля и начать работать. Git, Python и Node.js не нужны: код скачивается архивом, всё остальное собирается внутри контейнеров. Справочник по томам, резервным копиям и общему доступу — в [развёртывании](DEPLOYMENT.md).

## Что понадобится

| Что | Зачем |
| :--- | :--- |
| Docker Desktop (Windows, macOS) или Docker Engine с плагином Compose v2 (Linux) | Сборка и запуск трёх контейнеров: `agent`, `web`, `runner` |
| Интернет до GitHub, Docker Hub, PyPI и npm | Первая сборка скачивает базовые образы и зависимости. За корпоративным прокси без доступа к ним сборка упадёт на скачивании |
| Ключ модели | Без него сервер поднимется, но первый же ход ответит ошибкой авторизации. Для шлюза нужны ещё его адрес и имя модели |
| Браузер | Интерфейс открывается на `http://localhost:8080` |

## 1. Скачать код

Папку назовите `orbita` и потом не переименовывайте. По имени папки Compose называет тома (`orbita_data`, `orbita_threads`): после переименования он заведёт новые пустые тома, и документы с тредами «пропадут».

Windows, PowerShell. Пишите именно `curl.exe`: в Windows PowerShell 5.1 `curl` — псевдоним другой команды.

```powershell
cd $HOME; curl.exe -L -o orbita.tar.gz https://github.com/IST0VE/orbita-agent/archive/refs/heads/master.tar.gz; mkdir orbita; tar -xzf orbita.tar.gz -C orbita --strip-components=1; cd orbita
```

Linux и macOS:

```bash
mkdir -p ~/orbita && curl -L https://github.com/IST0VE/orbita-agent/archive/refs/heads/master.tar.gz | tar -xz -C ~/orbita --strip-components=1 && cd ~/orbita
```

`curl` и `tar` встроены в Windows 10/11, macOS и почти любой Linux. Архив сохраняет окончания строк и права: `up.cmd` приходит с CRLF, `up.sh` — исполняемым.

## 2. Заполнить `.env`

Если переносите Orbita с другой машины, положите её `.env` в корень папки, рядом с `docker-compose.yml`, и переходите к проверке адресов ниже. В `.env` лежат ключ модели и токены Jira и Confluence: переносите его флешкой или `scp`, не через git и не мессенджером.

Иначе создайте `.env` из шаблона: `Copy-Item .env.example .env` в PowerShell или `cp .env.example .env` в Linux. Затем впишите модель.

Модель по умолчанию — DeepSeek, достаточно ключа:

```dotenv
LLM_API_KEY=<ключ DeepSeek>
```

OpenAI-совместимый шлюз, например корпоративный или демо-шлюз с лимитами:

```dotenv
LLM_PROVIDER=openai
LLM_API_BASE=https://<адрес шлюза>/v1
LLM_MODEL=<имя модели на шлюзе>
LLM_API_KEY=<ключ шлюза>
LLM_MAX_RETRIES=4
LLM_REQUESTS_PER_MINUTE=<чуть меньше лимита шлюза>
LLM_TIMEOUT_S=300
```

- `LLM_MAX_RETRIES` больше двух. Отказ шлюза по лимиту приходит с `retry-after`, клиент ждёт и повторяет. Двух попыток на длинном прогоне не хватает, и он падает целиком.
- `LLM_REQUESTS_PER_MINUTE` ставит запросы в очередь до отправки, чтобы роль с инструментами не упиралась в 429 на середине.
- `LLM_TIMEOUT_S=300`: документ длинной роли (около 9 тысяч токенов) медленный шлюз за минуту не отдаёт. С таймаутом 60 с клиент обрывает запрос и повторяет его, и повторы впустую расходуют лимит токенов.

Для первого запуска выставьте безопасную публикацию — документы в файлы, задачи Jira не создавать:

```dotenv
PUBLISH_TARGET=file
JIRA_CREATE_ISSUES=0
```

`API_ADMIN_TOKEN` и `NT_RUNNER_TOKEN` оставьте пустыми: скрипт запуска сгенерирует их сам. `LLM_PROVIDER=anthropic` штатный образ не поддерживает — в нём нет этого адаптера; используйте `deepseek` или `openai`.

**Адреса в `.env`.** Внутри контейнера `127.0.0.1` и `localhost` означают сам контейнер. Для сервисов на этой же машине (Prometheus, Jira) пишите `host.docker.internal`. Адреса в локальной сети, например `192.168.x.x`, работают, только если новая машина в той же сети. Модель по HTTP допустима только на loopback, поэтому из Docker к ней нужен HTTPS — подробнее в [развёртывании](DEPLOYMENT.md#сервисы-на-этой-же-машине).

Для сценариев нагрузочного тестирования перенесите и `config/nt-runner.json` со списком стендов. Без него скрипт создаст шаблон с одной демо-целью.

## 3. Запустить

| Система | Команда из папки `orbita` |
| :--- | :--- |
| Windows | `.\up.cmd` или двойной щелчок по `up.cmd` |
| Linux / macOS | `./up.sh` |

Скрипт проверит `.env`, допишет недостающие токены, соберёт образы и поднимет три контейнера. Он дождётся их готовности и напишет **«Orbita запущена: http://localhost:8080»**. Первая сборка занимает несколько минут, повторный запуск — секунды.

Проверка: у `agent`, `web` и `runner` должен быть статус `healthy`.

```bash
docker compose ps
```

## 4. Если машина — удалённый сервер

Порты открыты только на `127.0.0.1` сервера, и это намеренно: API запускает платные вызовы модели и читает материалы задач. С ноутбука заходите через SSH-туннель, затем откройте `http://localhost:8080` у себя:

```bash
ssh -N -L 8080:127.0.0.1:8080 user@server
```

Не меняйте привязку портов на `0.0.0.0`. Для доступа команды нужен reverse proxy с TLS и индивидуальной аутентификацией, см. [SECURITY.md](../SECURITY.md).

## 5. Первый вход и первый результат

1. Откройте `http://localhost:8080`. Браузер спросит «Bearer-токен API (API_ADMIN_TOKEN)» — вставьте это значение из `.env`. Посмотреть его: `Select-String '^API_ADMIN_TOKEN' .env` в PowerShell или `grep '^API_ADMIN_TOKEN' .env` в Linux. Токен хранится в сессии вкладки, поэтому новая вкладка спросит снова.
2. В переключателе сценария в верхней строке выберите **«Архитектурная аналитика»** и нажмите «Новый прогон».
3. Слева, в «Материалах», выберите папку `partial-refund` — это готовый пример из репозитория.
4. Введите запрос и нажмите «Запустить»: *«Собери системные требования и проект решения по частичному возврату заказа. Укажи противоречия в источниках и открытые вопросы»*.
5. Следите за этапами на схеме, документами в левой колонке и консолью внизу. Через шлюз с лимитом около 20 запросов в минуту полный прогон может занять до получаса. Паузы между этапами — ожидание лимита, а не зависание.
6. На карточке **«Требуется подтверждение»** проверьте документ и нажмите «Подтвердить». Результат появится слева в «Опубликованных документах».

Документы хранятся в томе Docker, а не в папке `published/` на диске. Скопировать их в папку `published-export`:

```bash
docker compose cp agent:/data/published ./published-export
```

Что проверять в документах и что значат статусы публикации — в [руководстве пользователя](USER_GUIDE.md).

## 6. Повседневная работа

- **Свои материалы** кладите в `orbita/input/<задача>/`. Папка подключена к контейнеру, интерфейс видит её сразу, без перезапуска. Текстовые форматы и `.drawio` читаются напрямую; PDF и DOCX сначала переведите в текст. Подробнее — в [материалах задачи](INPUTS.md).
- **Настройки** меняйте в `.env` на машине, затем снова запустите `up.cmd` или `up.sh`: он пересоздаст изменившиеся контейнеры. Раздел «Настройки» в интерфейсе в Docker не достаёт до `.env` машины — смотреть там можно, сохранять бесполезно.
- **Вмешаться в идущий прогон** — кнопкой «Пауза», а не «Остановить». Пауза сохраняет сделанное и даёт дописать указание; после остановки прогон придётся запускать и оплачивать заново.
- **Стенды нагрузочного тестирования** — в `config/nt-runner.json`; после правки выполните `docker compose restart runner`.

| Что нужно | Команда |
| :--- | :--- |
| Журнал агента | `docker compose logs -f agent` |
| Состояние контейнеров | `docker compose ps` |
| Остановить | `docker compose down` — документы и треды остаются на томах |
| Запустить снова | `.\up.cmd` или `./up.sh` |

**Не запускайте `docker compose down -v`**: флаг `-v` удаляет тома вместе с документами и тредами.

## 7. Обновление

Скачайте свежий архив и распакуйте поверх той же папки. `.env`, `config/nt-runner.json` и ваших папок в `input/` в архиве нет, поэтому они не пострадают. Команды запускаются из папки `orbita` и сразу перезапускают Orbita.

Windows, PowerShell:

```powershell
curl.exe -L -o ..\orbita.tar.gz https://github.com/IST0VE/orbita-agent/archive/refs/heads/master.tar.gz; tar -xzf ..\orbita.tar.gz -C . --strip-components=1; .\up.cmd
```

Linux и macOS:

```bash
curl -L https://github.com/IST0VE/orbita-agent/archive/refs/heads/master.tar.gz | tar -xz -C . --strip-components=1 && ./up.sh
```

## 8. Перенос документов и тредов с другой машины

Нужен, только если на старой машине остались результаты, которые жалко терять. Имена томов там начинаются с имени её папки проекта в нижнем регистре: у папки `claude_langGraph` это `claude_langgraph_data` и `claude_langgraph_threads`. Проверьте их командой `docker volume ls` и подставьте вместо `old_data` и `old_threads` в первой команде.

На старой машине, из папки проекта. Агент и runner остановятся примерно на минуту:

```bash
docker compose stop agent runner; docker run --rm -v old_data:/data -v old_threads:/threads -v "${PWD}/backup:/to" alpine tar czf /to/orbita-backup.tar.gz -C / data threads; docker compose start agent runner
```

Скопируйте `backup/orbita-backup.tar.gz` в `orbita/backup/` на новой машине. После первого успешного запуска выполните там:

```bash
docker compose stop agent runner; docker run --rm -v orbita_data:/data -v orbita_threads:/threads -v "${PWD}/backup:/from" alpine sh -c "rm -rf /data/* /threads/* && tar xzf /from/orbita-backup.tar.gz -C /"; docker compose start agent runner
```

Обе команды работают и в bash, и в PowerShell. Формат тредов принадлежит серверу разработки LangGraph: они переносятся надёжно, пока `requirements.lock` на обеих машинах одинаковый. Если треды не открылись, документы всё равно на месте. Полная процедура копирования, включая журнал runner, — в [развёртывании](DEPLOYMENT.md#резервная-копия-и-восстановление).

## Если что-то не так

| Симптом | Что сделать |
| :--- | :--- |
| Скрипт: «В .env не задан LLM_API_KEY» | Впишите ключ модели в `.env` и запустите снова |
| Скрипт: «LLM_PROVIDER=anthropic не поддержан» | Выберите `deepseek` или `openai`, для Anthropic — [запуск без Docker](GETTING_STARTED.md) |
| `Docker Desktop is manually paused` или «Docker не запущен» | Снимите Docker Desktop с паузы или запустите его и дождитесь статуса Engine running |
| Linux: `permission denied ... docker.sock` | `sudo usermod -aG docker $USER`, затем выйдите из сеанса и войдите снова |
| Сборка падает на скачивании образов или пакетов | Нет доступа к Docker Hub, PyPI или npm: проверьте сеть и прокси машины |
| Скрипт: «Запуск не удался» | Над этой строкой скрипт уже вывел хвост журналов `agent` и `runner` — причина обычно там. Полный журнал: `docker compose logs --tail 100 agent` |
| Порт 8080 занят | `ORBITA_WEB_PORT=8088` в `.env`, запуск снова, адрес — `http://localhost:8088` |
| Порт 2024 занят | Остановите процесс на этом порту: его занимает агент, и в `.env` порт не меняется |
| В интерфейсе «Нет доступа» | Неверный токен. Обновите страницу и введите `API_ADMIN_TOKEN` из `.env` |
| В интерфейсе «Нет сервера» | Агент не отвечает: `docker compose ps` и журнал агента |
| Долгие паузы, в журнале 429 | Лимит шлюза. Проверьте `LLM_REQUESTS_PER_MINUTE`, `LLM_MAX_RETRIES` и `LLM_TIMEOUT_S` из шага 2 |
| Правка в «Настройках» не действует | В Docker настройки меняются только в `.env` на машине, затем `up.cmd` или `up.sh` |
| Документов нет в `published/` на диске | Они в томе Docker: `docker compose cp agent:/data/published ./published-export` |

Остальные ошибки описаны в [диагностике](TROUBLESHOOTING.md).
