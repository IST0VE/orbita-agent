# Диагностика

[Документация](README.md) / Решение проблем

**Сначала найдите границу сбоя:** доступен ли backend, видны ли файлы, отвечает ли модель, сохранён ли готовый результат. Это разные проверки, и успешная предыдущая не гарантирует следующую.

## Интерфейс и подключение

| Симптом | Причина, которую проверить | Что сделать |
| :--- | :--- | :--- |
| «Нет сервера», пустой список сценариев | Backend не запущен или другой порт | Проверить `/ok`, терминал backend и адрес прокси |
| UI открыт, но API-запросы не проходят | Запущена только статика/preview | Запустить dev frontend либо настроить API-прокси по [инструкции](DEPLOYMENT.md) |
| API вернул 401 | Нет верного Bearer-токена | Ввести `API_ADMIN_TOKEN` в запросе браузера; ключ модели здесь не подходит |
| При входе токен запрашивается несколько раз | Устаревший frontend повторно обрабатывает запоздавшие 401 параллельных запросов | Обновить frontend и перезагрузить страницу; один ввод должен обслужить все уже отправленные запросы |
| Прогон падает с `AuthenticationError` после чтения Jira | API модели отклонил ключ или доступ к выбранной модели | Проверить ошибку узла в состоянии треда и журнале backend. При `team_model_access_denied` выбрать разрешённую модель в `LLM_MODEL` и перезапустить backend. Сохранённое поле `model` в треде игнорируется |
| API вернул 503 с сообщением о токене | Токен не задан или имеет недопустимый формат | На сервере задать случайный `API_ADMIN_TOKEN` (32–256 ASCII-символов) и перезапустить |
| «Упрощённый интерфейс» | Manifest отсутствует или несовместим | Проверить backend/frontend одной версии, регистрацию графа и `/api/ui/capabilities` |
| После перезагрузки нет прежнего треда | Серверное состояние удалено или тред недоступен | Проверить runtime-хранилище; ID в браузере сам по себе не восстанавливает данные |
| Старая история при новой задаче | Повторно используется диалог | Нажать «Новый прогон» |

Проверка backend из PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:2024/ok
```

Для Docker: `docker compose logs --tail 100 agent`; если использовали дополнительный Compose-файл, передайте те же `-f`, что при запуске.

## Установка и запуск

| Симптом | Что сделать |
| :--- | :--- |
| `No module named agent` или `costmeter` | Установить `requirements.txt` из корня; использовать Python именно из `.venv` |
| Команда `langgraph` не найдена | Установить dev-зависимости и вызвать `.venv\Scripts\langgraph.exe` напрямую |
| PowerShell запрещает `npm.ps1` | Использовать `npm.cmd`; менять политику выполнения для этого не требуется |
| `test:engine` не понимает strip-types | Использовать Node 22, как в CI |
| Ошибка блокирующей операции | Запустить backend с `--allow-blocking` |
| `UnicodeEncodeError` / `charmap` в Windows | Выполнить `$env:PYTHONUTF8="1"` в терминале backend и повторить команду |
| `ConfigError` | Проверить указанную переменную: число, диапазон, `0/1`, допустимое имя режима |
| Ошибка импорта Anthropic | Установить `.[anthropic]` в используемое окружение/образ |
| Docker не понимает `env_file.required` | Версия Compose не поддерживает синтаксис штатного файла |

## Материалы не видны или не прочитаны

1. Проверьте, что файлы лежат **внутри отдельной папки** `input/my-task/`, а не просто в корне `input/`.
2. Проверьте `AGENT_INPUT_DIR` относительно рабочей папки backend.
3. Для Docker проверьте mount: локальная папка не появляется в контейнере автоматически.
4. Проверьте расширение и UTF-8. PDF/DOCX/картинки напрямую не читаются.
5. Обновите страницу и заново выберите папку/документы.

Сообщение о выходе за корень или недопустимом пути — ограничение файлового доступа. Положите материал в разрешённую папку, не передавайте `../` или системный путь.

Если документ обрезан, смотрите `AGENT_INPUT_MAX_CHARS`. В обновлении документа это общий лимит комплекта: сценарий откажется применять правки к неполному тексту. Для схем отдельно действует `DIAGRAM_MAX_CHARS`.

Если граф остановился с «Нет входа», дайте материал, соответствующий сценарию: пакет для сверки, `.drawio` для схемы, исходник и выбранные новые файлы для обновления. Один общий запрос «сделай документацию» не заменяет отсутствующий источник.

«Подготовка задачи» требует настроенную Jira даже при выбранных локальных файлах. Если нужен прогон только по папке без трекера, используйте «Архитектурную аналитику».

## Модель не отвечает

| Симптом | Проверить |
| :--- | :--- |
| 401 / 403 от LLM | Ключ, доступ к модели, нужный provider и API base |
| Модель не найдена | Точное имя модели на выбранном сервере; `LLM_MODEL` не подбирается при смене provider |
| Ошибка native tools | `LLM_TOOL_MODE`; для несовместимого шлюза предусмотрены `auto` и `prompt` |
| Таймаут на длинном документе | `LLM_TIMEOUT_S`, сеть и размер ответа; чрезмерно короткий таймаут вызывает повторную генерацию |
| Обрезанный текст или невалидный план | `LLM_MAX_TOKENS`, ответ модели и достаточность контекста |
| Стоимость нулевая с предупреждением | Нет тарифа модели; задать `PRICE_*`, не считать запуск бесплатным |
| Конвейер остановлен по бюджету | Накопленный расход всего треда и `BUDGET_USD_PER_THREAD` |
| Роль пишет «не успел посмотреть» и не открывает файлы | Исчерпан `TOOL_TURNS_PER_RUN`: роль сделала последний ход без инструментов. Поднимите потолок или сократите материал |
| Шлюз отказывает по частоте (429, «Rate limit», «limit resets at») | Минутный лимит шлюза: `LLM_REQUESTS_PER_MINUTE` и `LLM_TOKENS_PER_MINUTE` выстраивают запросы в очередь до отправки; `LLM_MAX_RETRIES` переживает единичный отказ, но ждёт минуту молча |
| Провайдер отказывает по числу токенов | Окно модели против размера запроса: `NT_BRIEF_TOKENS`, `NT_TOOL_RESULT_TOKENS` и `LLM_MAX_HISTORY_TOKENS` |

При долгом выполнении сначала проверьте журнал: возможно, идёт внешнее чтение с заданными паузами либо ожидается подтверждение. Не отправляйте повторную задачу для «пробуждения» interrupt.

### Отказ по размеру запроса в НТ

Отказ провайдера попадает в отчёт его же словами — раздел **Unverified assumptions**, запись `LLM_UNAVAILABLE`; полный текст с трассировкой лежит в журнале backend (`nt_llm_failed`). Там же перед каждым вызовом печатается, сколько ушло: `nt_investigate ... history_tokens=`.

Сколько запрос весит и помещается ли он в окно модели, считает отдельная команда — она не читает тест и не обращается к модели:

```powershell
.venv\Scripts\python.exe scripts/diagnose_nt.py --model-input --window 7000
```

Постоянная часть вызова — промпт роли и схемы включённых инструментов. Остальное занимают бриф расследования и накопленная переписка; при `--window` команда предлагает значения трёх переменных под это окно и возвращает ненулевой код, если запрос не помещается. Подробнее о потолках — в [конфигурации](CONFIGURATION.md#нагрузочное-тестирование) и [NT.md](NT.md#модель-и-проверка-гипотез).

## Документы написаны, но файлов нет

Проверьте последовательно:

1. Есть ли запрос **«ТРЕБУЕТСЯ ПОДТВЕРЖДЕНИЕ»** — без согласия запись ещё не выполнена.
2. `PUBLISH_TARGET`: `none` оставляет результат в треде, `confluence` пишет во внешнюю систему.
3. `CONFLUENCE_PUBLISH`: значение `0` выключает также локальную публикацию.
4. `CONFLUENCE_PUBLISH_MODE`: для обычного UI используйте `each`, а не `manual`.
5. Путь `PUBLISH_DIR` и право записи backend.
6. Статус каждого документа: `failed`, `partial`, `rejected` и `skipped` требуют прочитать причину.

В Docker `published` — путь внутри контейнера, если он не подключён отдельно. Кроме того, `.env` может перекрыть `PUBLISH_DIR` из Dockerfile. В [готовом варианте запуска](DEPLOYMENT.md) путь явно установлен в `/data/published`.

## Jira и Confluence

При 401/403 проверяйте не только действительность токена, но и права на конкретный проект, пространство или страницу. При 404 — адрес, REST-версию, ID и видимость объекта. Для Confluence v2 нужно изменить и `CONFLUENCE_API_VERSION`, и `CONFLUENCE_API_PATH`, а также указать `CONFLUENCE_SPACE_ID`.

Внешние ссылки читаются только для настроенного домена. Confluence `/x/...` и `/display/...` замените полной ссылкой с числовым page ID.

Если создана только часть задач или страниц, сначала проверьте список результатов и ссылки. Успешные объекты не откатываются. Новый полный прогон может создать дубликаты; он не является универсальной командой восстановления.

Форма Jira может не применить часть параметров URL. Проверьте поля вручную и скопируйте значения из карточки. Подробнее — [интеграции](INTEGRATIONS.md).

## Настройки сохранены, поведение прежнее

Локально перезапустите backend. Убедитесь, что переменная не задана окружением процесса: оно имеет приоритет над `.env`.

В Docker меняйте `.env` на хосте и пересоздавайте контейнер через `up -d --force-recreate agent`. Обычный `restart` не перечитывает `env_file`; UI не редактирует файл хоста в штатном образе.

## Проведение НТ (`nt_run`)

| Симптом | Что проверить |
| :--- | :--- |
| Нет графа в каталоге | `nt_run` зарегистрирован в `langgraph.json`; перезапустите backend и обновите каталог интерфейса |
| «Runner недоступен или не настроен» | Запущен `serve_nt_runner.py`, адрес `NT_RUNNER_URL` достижим из backend, токен совпадает в обоих процессах |
| На стенде всё настроено, но runner возвращает 401 | Runner сам не читает `.env.nt-testbed`; задайте общий токен в `.env` или его окружении |
| «Runner не смог подготовить сценарий» | Путь `k6_binary`, результат `k6 inspect`, конфигурация цели и её лимиты; `local-demo` в шаблоне не запускает HTTP-сервис |
| План не проходит лимиты | `target` должен быть ключом `targets`; длительность разгона плюс плато должна укладываться в `max_duration_seconds` |
| Основной тест не начался | Пробный тест должен завершиться с `completed`; проверьте ожидаемый HTTP-статус, body, данные, извлечение и авторизацию |
| `completed`, но анализ `INCONCLUSIVE` | Это разные статусы. Проверьте источники, карту метрик, покрытие периода и принадлежность рядов тесту |
| Ошибки в live-окне нулевые, в summary ненулевые | Окно содержит последние 5 секунд; summary — весь прогон. Это не обязательно противоречие |
| Новый тест блокируется, прежний `unknown` | Проверьте фактические процессы и используйте [локальное восстановление](NT_RUN.md#остановка-и-восстановление); не удаляйте SQLite ради повторного старта |
| НТ остановилось само | Смотрите `stop_reason`: `lease_expired`, `metrics_lost`, `deadline`, `error_threshold`, `latency_threshold` или `k6_exit_*` |

Для разбора сохраните `test_id`, план, `test_status`, `stop_reason`, `metrics`, `summary` и поля исторического анализа. Если нужен разбор действий модели, используйте [стенограмму](NT_RUN_TESTBED.md); одного итогового текста недостаточно.

## Что приложить к сообщению об ошибке

Укажите сценарий, действие, ожидаемый и фактический результат, способ запуска, версии Python/Node и текст ошибки. Полезны ID треда/прогона, список имён входных файлов, обезличенный минимальный пример и небольшой фрагмент журнала вокруг сбоя.

Не прикладывайте `.env`, токены и исходные корпоративные документы целиком. `docker compose config` может раскрыть подставленные секреты, поэтому его полный вывод не подходит для публичного issue.
