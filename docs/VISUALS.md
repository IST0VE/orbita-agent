# Иллюстрации документации

[Документация](README.md) / Поддержка иллюстраций

Снимки интерфейса в руководствах сняты скриптами с работающего портала по настоящим прогонам на стенде `nt-testbed`. Кадры, которые ещё не пересняты, остаются явными SVG-заглушками «место для скриншота»: они не подтверждают реализацию показанной функции. Устаревший кадр пересобирают тем же скриптом, а не правят руками.

## Как обновлять

Нужны стенд, стендовый backend и портал — те же процессы, что для [ручного прогона НТ](NT_RUN_TESTBED.md#вручную-через-интерфейс). Стендовый backend выбран намеренно: публикация у него идёт в файл, Jira и Confluence — моки, и прогон ради картинки ничего не создаёт в настоящих системах.

```powershell
.venv\Scripts\python.exe -m pip install -c requirements.lock -e ".[docs]"
.venv\Scripts\python.exe -m playwright install chromium
.venv\Scripts\python.exe scripts/shoot_portal.py --out .tmp/shots
```

1. Снимайте сначала во временную папку (`--out`) и просматривайте кадры; без `--out` скрипт пишет прямо в `docs/assets/screenshots/`. Отдельные сцены передаются именами: `shoot_portal.py agent drawio`.
2. Сцены `agent`, `drawio`, `jira` и `update` — настоящие прогоны: вызовы модели и записи в `PUBLISH_DIR`. Скрипт сам нажимает «Подтвердить» — это съёмка, а не согласование оператором.
3. Настройки снимайте с backend на обычном `.env`: стендовый честно предупреждает, что файл разошёлся с работающим процессом, и предупреждение попадёт в кадр. Токен тогда берётся из того же файла: `shoot_portal.py settings --env .env`.
4. Кадры НТ собирают `shoot_nt_portal.py` и `shoot_nt_run_portal.py` — порядок запуска описан в [стенде НТ](NT_RUN_TESTBED.md#автоматически-со-снимками-интерфейса). Второй проводит настоящую нагрузку через runner.
5. Прогон, который скрипт не дождался, можно доснять: `--thread <id>` открывает уже запущенный тред и продолжает с его остановки (`shoot_portal.py agent`, оба скрипта НТ). Журнал событий у такого треда пуст — интерфейс собирает его из живого потока.
6. Проверьте подписи под кадрами: они описывают, что на снимке, и цифры в тексте не должны расходиться с цифрами на картинке.

**Сколько это идёт.** На демо-шлюзе с qwen3.8-flash роль тратит 20–40 тысяч токенов ответа, большей частью на скрытые рассуждения, а шлюз пускает 30 тысяч за окно в 10–15 минут. Полный прогон аналитики занимает больше часа, draw.io и Jira — сопоставимо. Для съёмки на таком шлюзе нужны `LLM_TIMEOUT_S` в несколько минут и `LLM_MAX_RETRIES` в десятки: иначе длинный ответ обрывается по таймауту, а шлюз всё равно списывает сгенерированные токены. Ограничивать `LLM_MAX_TOKENS` нельзя — роль исчерпает лимит на рассуждениях и вернёт пустой документ.

Подписи кнопок и классы вёрстки, на которые опираются скрипты, собраны в `scripts/portal_shots.py`. После переоформления интерфейса начинать надо с него: старые скрипты после смены терминального фронта искали кнопку «[запустить]», которой больше нет.

На кадре не должно быть токенов и личных данных. Поля секретов в настройках показываются маской, но адреса сервисов видны — снимайте с того окружения, адреса которого можно показывать.

Схемы Mermaid храните рядом с поясняющим текстом. Для схемы развёртывания обозначайте процессы, сетевые границы и каталоги хранения; граф НТ должен показывать отдельные backend, runner, worker/k6 и цель нагрузки.
