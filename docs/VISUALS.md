# Схемы и скриншоты

[Документация](README.md) / Визуальные материалы

В руководства уже встроены схемы Mermaid и девять оформленных мест под реальные снимки интерфейса. Заглушки явно подписаны: они не изображают якобы выполненный запуск и не подменяют результат проверки.

## Визуальный подход

Документация использует сдержанную тёмную обложку, светлые текстовые страницы, спокойный бирюзовый акцент и последовательную нумерацию кадров. В Markdown оформление держится на иерархии заголовков, коротких абзацах, таблицах, схемах и подписях. HTML используется только для вводных блоков, чтобы страницы оставались читаемыми в обычном Markdown-просмотрщике.

Обложка: [`assets/cover.svg`](assets/cover.svg). Места для снимков: [`assets/screenshots/`](assets/screenshots/). Изображения подключены относительными ссылками и не зависят от внешнего хостинга.

## Как подготовить снимки

1. Используйте встроенные вымышленные материалы из `input/`, одинаковые ширину окна и масштаб браузера.
2. Для общего вида подойдёт кадр 1600 × 1000 или 1920 × 1200. Важнее читаемость текста, чем конкретное разрешение; не уменьшайте интерфейс до неразборчивого размера.
3. Для деталей обрежьте кадр по смыслу: выбранные файлы, окно согласования, фрагмент документа. Сохраняйте достаточно окружения, чтобы было понятно, где пользователь находится.
4. Отключите анимацию перед захватом, уберите DevTools, посторонние вкладки и уведомления.
5. Скрывайте ключи, реальные email, внутренние домены и корпоративные данные. Не исправляйте сгенерированный результат на картинке так, будто его выдал продукт.
6. Используйте PNG для UI. В подписи укажите сценарий и что демонстрирует кадр; при необходимости — версию/дату съёмки.

Для активного выполнения нужен реальный запуск с моделью. Для Jira допустим кадр согласования до создания, без отправки задач. Подпись должна отражать фактическое состояние: «карточки перед созданием», а не «успешно созданные задачи».

## Как заменить заглушку

Сохраните, например, `docs/assets/screenshots/workspace.png`. Найдите ссылки на `workspace.svg`:

```text
rg -n "workspace.svg" README.md README.en.md docs
```

Замените соответствующие пути на `.png`, обновите alt-текст и подписи: уберите слова «место для скриншота», добавьте фактическое описание кадра. SVG-заглушку можно оставить как шаблон либо удалить после проверки, что ссылок на неё больше нет.

Не сохраняйте PNG под расширением `.svg`: браузер и Markdown-просмотрщик должны видеть правильный тип файла. Перед добавлением проверьте, что изображение открывается локально и не содержит секретов.

Mermaid-блоки являются редактируемым исходником. Если просмотрщик не поддерживает Mermaid, экспортируйте схему в SVG и положите в `docs/assets/diagrams/`, затем вставьте изображение рядом с исходным блоком или вместо отображаемого блока. Не удаляйте исходное описание при экспорте.

Дополнительные места для схем: сетевое размещение вашего стенда в `DEPLOYMENT.md` и корпоративный поток публикации в `INTEGRATIONS.md`. Их стоит заполнять после выбора реальной инфраструктуры, чтобы не выдавать пример за развёрнутую систему.
