# Иллюстрации документации

[Документация](README.md) / Поддержка иллюстраций

Снимки интерфейса в руководствах сняты скриптами с работающего портала по настоящим прогонам на стенде `nt-testbed`. Кадры, которые не удалось пересобрать, остаются явными SVG-заглушками «место для скриншота»: они не подтверждают реализацию показанной функции. Устаревший кадр пересобирают тем же скриптом, а не правят руками.

Последняя пересъёмка — 29 сентября 2026 года, после того как консоль «Выполнение» слилась с колонкой чата, а список чатов стал общим для всех сценариев. Кадры показывают эту раскладку: слева «Чаты», в центре схема и композер, справа вкладка «Чат» с файлами, лентой прогона и результатами.

## Как обновлять

Нужны стенд, стендовый backend и портал — те же процессы, что для [ручного прогона НТ](NT_RUN_TESTBED.md#вручную-через-интерфейс). Стендовый backend выбран намеренно: публикация у него идёт в файл, Jira и Confluence — моки, и прогон ради картинки ничего не создаёт в настоящих системах.

Стенду для съёмки нужно чистое состояние: список чатов слева и «Опубликованные документы» справа попадают в каждый кадр, а на рабочей машине там копятся прогоны разработки. Поэтому перед съёмкой уберите папку `.langgraph_api/` в сторону (без удаления: в ней история вашей разработки) и направьте публикации в пустую папку. Вход через Keycloak стендовый backend отключает сам — скрипты ходят с токеном администратора.

```powershell
Move-Item .langgraph_api .tmp\langgraph_api.dev-backup    # вернуть после съёмки
New-Item -ItemType Directory -Force .tmp\shots-published
.venv\Scripts\python.exe scripts/serve_nt_testbed.py --publish-dir .tmp/shots-published
```

Затем в другом терминале:

```powershell
.venv\Scripts\python.exe -m pip install -c requirements.lock -e ".[docs]"
.venv\Scripts\python.exe -m playwright install chromium
.venv\Scripts\python.exe scripts/shoot_portal.py --out .tmp/shots
```

1. Снимайте сначала во временную папку (`--out`) и просматривайте кадры; без `--out` скрипт пишет прямо в `docs/assets/screenshots/`. Отдельные сцены передаются именами: `shoot_portal.py agent drawio`. Чаты сцен остаются в списке слева, поэтому первыми снимайте `start`, `scenarios` и `library`, пока список пуст.
2. Сцены `agent`, `drawio`, `jira` и `update` — настоящие прогоны: вызовы модели и записи в `PUBLISH_DIR`. Скрипт сам нажимает «Подтвердить» — это съёмка, а не согласование оператором. После ответа карточка подтверждения не исчезает: следующая остановка приходит в тот же элемент. Скрипт ждёт, пока кнопка оживёт снова, и **не перезагружает страницу**: закрытый поток отменяет прогон, и снимать будет нечего.
3. Материалы кладутся в чат так же, как это делает оператор: значок книги («Добавить из библиотеки»), пример из `input/`, кнопка «В чат». Роли файлов у сцены `update` отмечаются кнопками «основной» и «материал». Сцена `jira` кладёт пакет в чат загрузкой с диска: к ней в «Моих документах» библиотеки уже накопились публикации, и длинный список прячет папки примеров под футером окна — окно при этом не прокручивается.
4. Настройки снимайте отдельно, с backend без стендовой подмены: стендовый честно предупреждает, что файл разошёлся с работающим процессом, и предупреждение попадёт в кадр. Сделайте копию `.env` с пустым `OIDC_ISSUER` (в `.tmp/`, она не попадает в git) и поднимите backend по ней. Токен скрипт берёт из той же копии:

   ```powershell
   Copy-Item .env .tmp\settings.env    # в копии очистите OIDC_ISSUER
   .venv\Scripts\python.exe scripts/serve_nt_testbed.py --env-file .tmp/settings.env
   .venv\Scripts\python.exe scripts/shoot_portal.py settings --env .tmp/settings.env
   ```

   Копию с секретами удалите после съёмки.
5. Кадры НТ собирают `shoot_nt_portal.py` и `shoot_nt_run_portal.py` — порядок запуска описан в [стенде НТ](NT_RUN_TESTBED.md#автоматически-со-снимками-интерфейса). Второй проводит настоящую нагрузку через runner. `NT_RUNNER_TOKEN` у runner и у стендового backend должен быть одним: runner читает только `.env`, а backend накладывает `.env.nt-testbed`, и при разных значениях граф сообщает «runner недоступен или не настроен». Задайте токен стенда в окружении процесса runner.
6. Прогон, который скрипт не дождался, можно доснять: `--thread <id>` открывает уже запущенный чат и продолжает с его остановки (`shoot_portal.py agent`, оба скрипта НТ). Журнал событий у такого чата пуст — интерфейс собирает его из живого потока.
7. Проверьте подписи под кадрами: они описывают, что на снимке, и цифры в тексте не должны расходиться с цифрами на картинке.

**Сколько это идёт.** На демо-шлюзе с qwen3.8-flash-next при лимитах 60 запросов и 300 тысяч токенов в минуту прогон аналитики из пяти ролей занял около четверти часа, анализ НТ — около пяти минут. Скорость ответа — порядка 28 токенов в секунду, а шлюз изредка обрывает соединение на длинном ответе (`RemoteProtocolError`): клиент повторяет запрос, и одна такая роль может стоить несколько минут. Для съёмки нужны `LLM_TIMEOUT_S` в несколько минут и `LLM_MAX_RETRIES` побольше двух. Сервер разработки выполняет один прогон за раз, поэтому сцены идут строго по очереди.

Подписи кнопок и классы вёрстки, на которые опираются скрипты, собраны в `scripts/portal_shots.py`. После переоформления интерфейса начинать надо с него: старые скрипты после смены терминального фронта искали кнопку «[запустить]», которой больше нет, а после слияния консоли с колонкой чата — нижнюю консоль и её вкладки «Поток»/«События». Событий теперь ищут во второй вкладке правой колонки: до прогона она называется «Сценарий», после — «Прогон».

На кадре не должно быть токенов и личных данных. Поля секретов в настройках показываются маской, но адреса сервисов видны — снимайте с того окружения, адреса которого можно показывать.

Схемы Mermaid храните рядом с поясняющим текстом. Для схемы развёртывания обозначайте процессы, сетевые границы и каталоги хранения; граф НТ должен показывать отдельные backend, runner, worker/k6 и цель нагрузки.
