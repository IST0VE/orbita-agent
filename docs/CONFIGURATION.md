# Конфигурация

[Документация](README.md) / Настройки

**Настройки backend находятся в `.env` в корне проекта.** Готовый шаблон — [`.env.example`](../.env.example), правила чтения — [`config.py`](../src/agent/config.py). Для первого запуска достаточно ключа, доступной модели и локальной публикации.

## Как применять изменения

1. Измените `.env` в редакторе или через `[настройки]` в интерфейсе.
2. Сохраните файл.
3. Перезапустите backend. Для Docker после изменения `env_file` пересоздайте контейнер — [инструкция](DEPLOYMENT.md).

Переменные окружения процесса имеют приоритет над `.env`. Пустое значение обычно означает «использовать значение по умолчанию». Булевы параметры удобно писать как `1` и `0`; числа — с точкой, например `0.50`. Неправильный формат вызывает ошибку конфигурации.

Относительные пути считаются от рабочей папки backend. Запускайте его из корня проекта. Ключ модели не нужно добавлять в `web/`: frontend обращается к backend, а не напрямую к провайдеру.

## Модель

Модель для всех тредов задаёт серверная `LLM_MODEL`. Поля `configurable.model`
и `context.model` (в том числе сохранённые в Assistant/Thread) игнорируются.
После смены модели перезапустите backend; удалять старые треды не требуется.

| Переменная | Значение в шаблоне | Назначение |
| :--- | :--- | :--- |
| `LLM_PROVIDER` | `deepseek` | `deepseek`, `openai` или `anthropic` |
| `LLM_MODEL` | `deepseek-v4-flash` | Точное имя доступной модели; не меняется автоматически вместе с провайдером |
| `LLM_API_KEY` | пусто | Ключ API; адаптеры также могут читать `DEEPSEEK_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` |
| `LLM_API_BASE` | пусто | Переопределение адреса API, например для корпоративного шлюза |
| `LLM_TOOL_MODE` | `auto` | Выбор протокола инструментов |
| `LLM_TEMPERATURE` | `0` | Параметр генерации |
| `LLM_MAX_RETRIES` | `2` | Повторы запросов при поддерживаемых клиентом временных ошибках |
| `LLM_MAX_TOKENS` | пусто | Ограничение длины ответа; пусто — поведение адаптера |
| `LLM_TIMEOUT_S` | пусто | Таймаут одного запроса; пусто — поведение клиента |
| `LLM_MAX_HISTORY_TOKENS` | пусто | Ограничение истории; по умолчанию `0`, без обрезки |

OpenAI-совместимый шлюз подключается через `LLM_PROVIDER=openai`, собственные `LLM_API_BASE`, `LLM_MODEL` и ключ. Для Anthropic нужен дополнительный Python-пакет: `pip install -e ".[anthropic]"` после основной установки. Актуальность доступа к конкретной модели проверяется у вашего провайдера; имя в шаблоне не гарантирует доступность для любого аккаунта.

| Режим инструментов | Поведение реализации |
| :--- | :--- |
| `auto` | Использует native tools и при распознанном отказе совместимости может перейти к JSON в тексте |
| `native` | Только API tools; сервер модели должен поддерживать этот протокол |
| `prompt` | Модель возвращает JSON в тексте; инструменты всё равно исполняет backend |

Низкий `LLM_MAX_TOKENS` может обрезать документ или машинный план. Маленький таймаут не ускоряет генерацию: длинный ответ может не успеть завершиться.

## Стоимость и бюджет

Параметр `BUDGET_USD_PER_THREAD` задаёт бюджет **всего треда**, включая предыдущие прогоны в нём. Значение `0` отключает ограничение. Проверка выполняется перед модельными вызовами и использует уже накопленную стоимость. Один следующий вызов может превысить оставшийся бюджет — это не банковский лимит и не предварительное резервирование средств.

Параметр `TOOL_TURNS_PER_RUN` ограничивает не деньги, а число ходов: сколько раз за один прогон роль может обратиться к инструментам. По умолчанию 12, значение `0` снимает потолок. Решение «спросить ещё раз» принимает модель, и на выключенном бюджете у этой петли не остаётся другого тормоза, кроме `recursion_limit` LangGraph — тысяч шагов и обрыва ошибкой. Исчерпав потолок, роль делает последний ход без инструментов и пишет документ по тому, что успела прочитать, отмечая в нём непросмотренное. Потолок действует на прогон, а не на тред: следующий запрос в том же треде получает его заново.

Тарифы берутся из [`prices.toml`](../packages/costmeter/src/costmeter/prices.toml) по паре провайдер/модель. Это снимок данных пакета, а не запрос текущего тарифа. Для своей модели или договора задайте цены вручную, в USD за миллион токенов:

| Переменная | Что считается |
| :--- | :--- |
| `PRICE_CACHE_HIT_PER_MTOK` | Входные токены из кеша |
| `PRICE_CACHE_MISS_PER_MTOK` | Входные токены вне кеша |
| `PRICE_OUTPUT_PER_MTOK` | Выходные токены |
| `PRICE_CACHE_WRITE_PER_MTOK` | Запись кеша для провайдеров с отдельной категорией |

Не переносите числа из исторических замеров как текущие цены. Если тариф неизвестен, ориентироваться на сумму и бюджет нельзя, пока он не настроен. Подробнее — [costmeter](../packages/costmeter/README.md).

## Куда сохранять документы

| `PUBLISH_TARGET` | Поведение |
| :--- | :--- |
| `file` | Markdown на диске в `PUBLISH_DIR` |
| `confluence` | Только Confluence; при недостающей конфигурации нет автоматического перехода к файлам |
| `auto` | Confluence, если обязательные реквизиты заполнены, иначе файлы |
| `none` | Документы остаются в состоянии треда |

`auto` выбирает цель по наличию настроек. Ошибка сети или авторизации Confluence после этого выбора не переключает публикацию на диск.

| Переменная | Шаблон | Назначение |
| :--- | :--- | :--- |
| `PUBLISH_DIR` | `published` | Папка локальных результатов |
| `PUBLISH_REQUIRE_APPROVAL` | `1` | Подтверждение перед записью документов |
| `CONFLUENCE_PUBLISH` | `1` | **Общий выключатель публикации, включая файлы**; историческое имя |
| `CONFLUENCE_PUBLISH_MODE` | `each` | `each`, `changed`, `manual` |

`each` публикует при каждом подходящем прогоне; `changed` пропускает неизменившееся содержимое; `manual` требует разрешения публикации в конфигурации запуска. Для обычной работы через UI оставьте `each` и используйте подтверждение. `prep` и `audit` собирают роли в одну страницу. Сценарий `update` использует собственный процесс сохранения отдельной версии и всегда запрашивает подтверждение.

## База знаний и память

| Переменная | Шаблон | Назначение |
| :--- | :--- | :--- |
| `KNOWLEDGE_ENABLED` | `0` | Включить подбор справочных документов |
| `KNOWLEDGE_DIR` | пусто | Папка с `*.md`; пусто — встроенные справочные разделы |
| `KNOWLEDGE_TOP_K` | `2` | Число подставляемых документов |
| `KNOWLEDGE_MIN_SCORE` | `0.05` | Порог релевантности |
| `MEMORY_ENABLED` | `1` | Память между тредами, если передан store |
| `MEMORY_NAMESPACE` | `orbita` | Пространство имён памяти |

Для собственной справки создайте, например, `knowledge/` с Markdown-файлами и укажите этот путь в `KNOWLEDGE_DIR`. Это отдельный источник стандартов, а не замена папке конкретной задачи. Память не является произвольной базой знаний по всем проектам: она связывает факты с распознанным аккаунтом.

## API, хранение и демо

| Переменная | Шаблон | Назначение |
| :--- | :--- | :--- |
| `API_ADMIN_TOKEN` | пусто → HTTP 503 | Обязательный Bearer-токен всего API; 32–256 ASCII-символов, задаётся только на сервере |
| `API_MAX_REQUEST_BYTES` | `65536` | Лимит тела запроса служебного API |
| `CHECKPOINT_BACKEND` | `memory` | `memory` или `postgres` для собственного Python-рантайма |
| `POSTGRES_URI` | Локальное подключение из шаблона | URI PostgreSQL для собственного рантайма |
| `DEMO_THREAD_ID` | `demo-thread-1` | Тред трёх ходов `run_demo.py` |
| `DEMO_ANSWER_CHARS` | `600` | Ограничение печати ответа демо, не генерации |

`langgraph dev` управляет состоянием сам. `CHECKPOINT_BACKEND=postgres` не переносит его треды в PostgreSQL: эти настройки нужны `run_demo.py` и коду, использующему `open_checkpointer()` / `open_store()`.

`VITE_API_URL` — отдельная переменная frontend. В обычном локальном запуске оставьте её незаданной: работает прокси Vite. При раздельном размещении настройте адрес и маршрутизацию по [инструкции развёртывания](DEPLOYMENT.md).
