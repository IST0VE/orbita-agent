# Метрики, Prometheus и Grafana

Агент отдаёт метрики в формате Prometheus на `/metrics` своего порта (`:2024`). Там же, на том же адресе, свои метрики публикует сервер LangGraph. В Compose их собирает Prometheus, а Grafana рисует по ним доску «Orbita»: деньги и токены, время ответа модели и окно шлюза, прогоны графов, запросы к Jira и Confluence, состояние самого сервера.

## Включить

Prometheus и Grafana подключены через профиль `monitoring`, как Keycloak через профиль `auth`. Без профиля они не запускаются. Чтобы профиль поднимали и `up.cmd` / `up.sh`, допишите его в `.env`:

```
COMPOSE_PROFILES=monitoring
```

Если там уже есть `auth`, перечислите профили через запятую: `COMPOSE_PROFILES=auth,monitoring`. Затем запустите `up.cmd` или `./up.sh`. Скрипт сам запишет в `.env` случайный `METRICS_TOKEN`, дождётся готовности всех сервисов и выведет адрес Grafana. Можно обойтись и без скрипта:

```bash
docker compose --profile monitoring up -d
```

В этом случае `METRICS_TOKEN` (случайная строка от 16 символов) впишите в `.env` сами. Без него Prometheus не стартует и объяснит почему.

| Что | Адрес | Порт меняет |
| :--- | :--- | :--- |
| Grafana, доска «Orbita» | http://localhost:3000 | `ORBITA_GRAFANA_PORT` |
| Prometheus | http://localhost:9090 | `ORBITA_PROMETHEUS_PORT` |

Оба порта открыты только на петлю, как порты агента и интерфейса. Смотреть доску можно без входа. Чтобы что-то менять в Grafana, войдите как `admin` с паролем `GRAFANA_ADMIN_PASSWORD` (по умолчанию `admin`). Пароль задаётся один раз, когда создаётся том `grafana`; потом его меняют уже в самой Grafana.

## Доска

Доска открывается как домашняя страница Grafana. Переменные вверху сужают панели: «Граф» — до одного или нескольких конвейеров, «Узел» — до выбранных узлов.

- **Сводка за период.** Отвечает ли агент; сколько потрачено и сколько сэкономил кеш; доля входа из кеша; сколько было вызовов модели, из них без тарифа; сколько прогонов, из них с ошибкой.
- **Модель.** Запросы в минуту по исходу (`ok`, `rate_limited`, `timeout`, `error`), время ответа p50/p95 по модели, токены по статьям, расход в час по графам, расход по ролям за период, попадание в кеш по графам.
- **Шлюз модели.** Заполнение минутного окна запросами и токенами рядом с лимитами `LLM_REQUESTS_PER_MINUTE` и `LLM_TOKENS_PER_MINUTE`, ожидание места в окне перед отправкой, остаток паузы после ответа 429.
- **Прогоны графов.** Таблица прогонов за период по исходам, прогоны, которые идут сейчас, длительность прогона.
- **Узлы.** Таблица за период: сколько раз узел запускался, сколько из них упал и сколько раз встал на подтверждение, среднее и p95 времени, суммарное время. По умолчанию строки отсортированы по суммарному времени, поэтому наверху — узлы, на которые уходит больше всего времени. Ниже — запуски узлов и время в них по интервалам.
- **Инструменты модели.** Что роли вызывали внутри узла `tools`: `list_task_files`, `read_task_file`, `jira_issue`, `jira_search`, `confluence_search`, `confluence_page`, инструменты НТ. По каждому — число вызовов и время. Узел `tools` в таблице узлов — это сумма этих вызовов за шаг.
- **Jira и Confluence.** Запросы по кодам ответа (каждая попытка отдельно, `network` — ответа не было) и время ответа.
- **Сервер агента.** Запросы к API по кодам ответа, включая отказы входа 401 и 403; время ответа по маршрутам; предупреждения и ошибки журнала; память, CPU и занятые воркеры LangGraph.

Доска лежит в репозитории: [`config/grafana/dashboards/orbita.json`](../config/grafana/dashboards/orbita.json). Из интерфейса Grafana её не сохранить. Чтобы изменить, экспортируйте изменённую доску (Export → JSON) поверх этого файла: Grafana перечитывает его каждые 30 секунд.

## Что измеряется

Метки принимают значения только из закрытых множеств: граф (ключ из `langgraph.json`), узел графа, модель, система, исход. Идентификаторы тредов, пользователей и путей с параметрами в метки не попадают.

| Метрика | Метки | Что это |
| :--- | :--- | :--- |
| `orbita_llm_requests_total` | `graph`, `node`, `outcome` | Запросы к модели. Каждая попытка отдельно, повторы тоже |
| `orbita_llm_request_duration_seconds` | `graph`, `model` | Время ответа модели без ожидания в очереди шлюза |
| `orbita_llm_requests_in_flight` | — | Запросы, ждущие ответа |
| `orbita_llm_tokens_total` | `graph`, `node`, `kind` | Токены: `cache_hit`, `cache_miss`, `cache_write` — вход, `output` — ответ |
| `orbita_llm_cost_usd_total` | `graph`, `node` | Стоимость по тарифу на момент вызова, $ |
| `orbita_llm_cost_without_cache_usd_total` | `graph`, `node` | Сколько стоили бы те же вызовы без кеша, $ |
| `orbita_llm_unpriced_requests_total` | `graph` | Ответы по неизвестному тарифу: в стоимость не вошли |
| `orbita_llm_queue_wait_seconds` | — | Ожидание места в минутном окне шлюза перед отправкой |
| `orbita_llm_window_requests`, `orbita_llm_window_tokens` | — | Сколько запросов и токенов в окне шлюза сейчас |
| `orbita_llm_limit_requests_per_minute`, `orbita_llm_limit_tokens_per_minute` | — | Лимиты из `.env`, `0` — без лимита |
| `orbita_llm_gateway_pause_seconds` | — | Остаток паузы после ответа шлюза 429 |
| `orbita_graph_runs_total` | `graph`, `outcome` | Прогоны: `completed`, `interrupted` (пауза на подтверждение), `failed`, `cancelled` |
| `orbita_graph_run_duration_seconds` | `graph`, `outcome` | Длительность прогона |
| `orbita_graph_runs_in_progress` | `graph` | Прогоны, которые идут сейчас |
| `orbita_graph_node_runs_total` | `graph`, `node`, `outcome` | Запуски узла: `ok`, `failed` — исключение, `interrupted` — пауза на подтверждение |
| `orbita_graph_node_duration_seconds` | `graph`, `node` | Длительность узла, завершившегося без ошибки |
| `orbita_tool_calls_total` | `graph`, `tool` | Вызовы инструментов моделью, в том числе походы в Jira и Confluence |
| `orbita_tool_duration_seconds` | `graph`, `tool` | Время одного вызова инструмента |
| `orbita_integration_requests_total` | `system`, `method`, `status` | HTTP-запросы к Jira и Confluence по коду ответа |
| `orbita_integration_request_duration_seconds` | `system`, `method` | Время одного такого запроса |
| `orbita_http_requests_total` | `route`, `method`, `status` | Запросы к API агента, кроме `/ok` и `/metrics` |
| `orbita_http_request_duration_seconds` | `route`, `method` | Время до начала ответа; у потока прогона — до первого байта |
| `orbita_log_records_total` | `level`, `logger` | Предупреждения и ошибки журнала — те же, что на странице «Журнал» |
| `orbita_info` | `version`, `provider`, `model` | Версия агента и модель по умолчанию |

Сервер LangGraph публикует рядом свои метрики: `lg_api_http_requests_*` (встроенные роуты), `lg_api_workers_*` (воркеры прогонов), а также `process_*` и `python_*` (память, CPU и сборщик мусора процесса).

Как их читать:

- **Продолжение после паузы — новый прогон.** Тред, остановленный на подтверждение, даёт один прогон с исходом `interrupted`, а после ответа оператора — ещё один. Так же и узел: остановка — запуск с исходом `interrupted`, продолжение — ещё один запуск.
- **У инструментов нет исхода.** Недоступную Jira или ненастроенный Confluence инструмент сообщает модели текстом, а не исключением. Число «ошибок» по инструментам вводило бы в заблуждение, поэтому отказы систем смотрите в ряду «Jira и Confluence» (коды HTTP) и на странице «Журнал».
- **Деньги считаются только для моделей с тарифом.** Если модели нет в `packages/costmeter/src/costmeter/prices.toml` и в `.env` не заданы `PRICE_*`, её вызовы попадают в «Без тарифа», а «Потрачено» остаётся нулём. Ноль в этом случае значит «неизвестно», а не «бесплатно».
- **Метрики — сумма по всем тредам.** Лимит треда (`BUDGET_USD_PER_THREAD`) проверяется по состоянию самого треда, а не по этим цифрам.
- **Счётчики живут в памяти процесса.** Пересоздание контейнера агента их обнуляет. Prometheus такие сбросы распознаёт, так что `increase()` и `rate()` на доске не проваливаются. Сами ряды хранятся на томе `prometheus`.
- **Ряды графов создаются при запуске.** Для каждого графа, каждого его узла и инструмента ряд заводится сразу с нулём, иначе `increase()` не показал бы первый прогон или первый вызов роли. Исключение одно: граф `nt`, который `nt_run` запускает внутри своего узла, выдаёт вызовы модели под именем `nt_run` с узлами `nt`, и первый такой вызов на каждый узел за жизнь процесса в прирост не попадает.

## Доступ

`/metrics` закрыт, как и весь API. Открывают его:

- `METRICS_TOKEN` — только `GET /metrics`. С ним же `/api/*`, треды и прогоны отвечают 401. Этот токен Prometheus читает из файла, который записывает точка входа его контейнера;
- `API_ADMIN_TOKEN` и вход пользователя через OIDC, как и для остального API.

`METRICS_TOKEN` короче 16 символов не принимается совсем. Из интерфейса «Настройки» токен не меняется. Если его сменили в `.env`, выполните `docker compose up -d` (или `up.cmd` / `up.sh`): пересоздадутся и агент, и Prometheus.

## Хранение

| Том | Что там |
| :--- | :--- |
| `prometheus` | Ряды метрик. Срок хранения задаёт `PROMETHEUS_RETENTION` (по умолчанию `30d`); рядов у агента сотни, поэтому том растёт на единицы мегабайт в день |
| `grafana` | База Grafana: пароль администратора и личные настройки. Доска и источник данных в ней не хранятся, они приезжают из `config/grafana` |

Конфигурация Prometheus лежит в [`config/prometheus/prometheus.yml`](../config/prometheus/prometheus.yml). После правки выполните `docker compose --profile monitoring restart prometheus`.

## Агент без Docker

Если сервер запущен командой `langgraph dev` на хосте, метрики доступны по адресу `http://127.0.0.1:2024/metrics`. Чтобы собирать их своим Prometheus, добавьте задание с `authorization: {type: Bearer, credentials: <METRICS_TOKEN>}`. Если Prometheus работает в контейнере, укажите в качестве цели `host.docker.internal:2024`.

## Если что-то не так

| Что видно | Причина и что сделать |
| :--- | :--- |
| Контейнер `prometheus` сразу завершается | В `.env` пустой или слишком короткий `METRICS_TOKEN`. Запустите `up.cmd` / `up.sh` — скрипт его создаст |
| В Prometheus → Status → Targets цель `orbita-agent` в состоянии `down` с 401 | Токены у агента и Prometheus разные: `.env` правили без пересоздания. Выполните `docker compose up -d` |
| Плитка «Агент» — «не отвечает» | Агент не запущен или ещё стартует; `docker compose ps`, `docker compose logs agent` |
| «Потрачено» — `$0`, а «Без тарифа» не ноль | У модели нет тарифа: задайте `PRICE_CACHE_HIT_PER_MTOK`, `PRICE_CACHE_MISS_PER_MTOK`, `PRICE_OUTPUT_PER_MTOK` |
| Панели прогонов пустые | Прогонов в выбранном периоде не было. Растяните период или запустите граф |
