# Ревью и переработка визуализации графа

Дата: 18 сентября 2026. Область ревью — фронтенд схемы выполнения: получение топологии, раскладка, геометрия стрелок, жесты, масштаб, выбор узла, жизненный цикл и проверки. Логика исполнения Python/LangGraph не переписывалась.

## Найденные причины

| Приоритет | Проблема прежней реализации | Последствие | Изменение |
| --- | --- | --- | --- |
| Высокий | `GraphCanvas` включал `panOnDrag` только во вкладке «Интерактивно» | Основная схема не реагировала на ожидаемый жест мышью | Один React Flow viewport, одинаковые жесты в обоих графических видах |
| Высокий | `GraphDiagram` рисовал неподвижные HTML-кнопки | Переставить карточку было невозможно | Управляемые позиции узлов и штатное перетаскивание React Flow |
| Высокий | Стрелка строилась только по двум коробкам, без препятствий и отдельных портов | Обратные переходы, общие ветки и петли пересекали карточки; несколько рёбер накладывались | ELK с фиксированными портами и ортогональной трассировкой; пересчёт маршрута при ручном движении |
| Высокий | Топологическая сортировка обрабатывала граф как DAG | Циклы `requirements → tools → requirements` и зависимые узлы оказывались в неверных слоях | Слоистая раскладка ELK, поддерживающая циклы, петли, компоненты и параллельные связи |
| Средний | Масштаб был смесью CSS scale, scrollLeft/Top и измеряемой подложки | Ограниченное перемещение, несколько источников геометрии и проблемы на границах прокрутки | Единая камера `{x, y, zoom}`; без прокручиваемой подложки для схемы |
| Средний | Раскладка запускалась при смене вида; документ размонтировал `GraphCanvas` | Сбрасывались положения и камера | Граф остаётся смонтированным; состояние камеры и ручные координаты отделены от runtime |
| Средний | Мини-карта была декоративной, без видимой области и навигации | Не помогала найти текущее место в длинном графе | Штатная MiniMap с рамкой viewport, перемещением и масштабированием |
| Средний | «По ширине» ограничивалось минимумом 30% и не учитывало высоту | Большой граф всё равно обрезался | «Весь граф» учитывает обе оси, минимальный масштаб 2%; при первом показе длинного графа сохраняется читаемость |
| Средний | Hover сдвигал карточку CSS transform независимо от SVG | Видимый край узла расходился с концом связи | Hover меняет только оформление, геометрия остаётся общей |
| Средний | Прежние браузерные тесты проверяли контейнер `.graph` | Пустая или сломанная схема могла пройти проверки | Новые проверки ждут реальные узлы и рёбра и отправляют мышь, колесо, touch и клавиатуру |

## Новая структура

- `lib/graph.ts`: серверная топология и семантика переходов. Клиент не содержит отдельной копии рабочего конвейера.
- `canvas/layout.ts`: адаптер топологии к ELK, реальные размеры карточек и портов, исходные позиции и маршруты. `rank/order` используются как предпочтения порядка модели, а не абсолютные пиксельные колонки. Алгоритм учитывает связи и циклы.
- ELK API запускает поставляемый библиотекой worker как отдельный статический ресурс. Раскладка не блокирует основной поток. Ошибка или таймаут оставляют понятное состояние с повторным запуском; cleanup прекращает устаревший расчёт.
- `canvas/GraphDiagram.tsx`: React Flow, карточки и рёбра, пользовательские позиции, выбор, камера. Ключ раскладки зависит от топологии и подсказок, а не от ссылочной идентичности runtime.
- `canvas/routing.ts`: чистая геометрия. Сохраняет корректные полосы ELK; при изменении проверяет простые коридоры и затем ищет ортогональный маршрут по свободным линиям. Индексы занятых интервалов ускоряют проверку пересечений. Короткий зазор уменьшает длину выхода из порта.
- `canvas/useEdgeRoutes.ts` и `routing.worker.ts`: для графов больше 50 узлов дорогая ручная маршрутизация выполняется вне основного потока. В очереди один активный расчёт и только последнее ожидающее положение; устаревший результат не применяется. Во время расчёта концы связей продолжают следовать за узлами.
- `canvas/GraphCanvas.tsx`: виды, поиск и панели. Список использует собственный `ZoomPane`; граф не использует его scroll/scale механику.
- `app/Workspace.tsx`: документ временно скрывает граф, сохраняя экземпляр и состояние.

Выбор и статус меняют оформление, не позиции. Начальная расстановка и ручные координаты не записываются в серверную топологию. Новый граф и перезагрузка страницы начинают новую сессию расстановки. Авторасстановка выполняется отдельным действием.

## Проверка

```powershell
cd web
npm.cmd run build
npm.cmd run test:engine
cd ..
.venv/Scripts/python.exe web/tests/browser_canvas.py
.venv/Scripts/python.exe web/tests/browser_regressions.py
```

Геометрические проверки охватывают циклы, самопетли, параллельные рёбра, недостижимый узел, пустую топологию, некорректную ссылку на узел, отрицательные координаты, узкие зазоры и ручную перестановку. Проверяются действительные границы карточек, точки начала/конца и отсутствие пересечений с внутренностью узлов.

Браузерный сценарий использует самостоятельный HTTP fixture, без модели и рабочего backend. В нём есть конвейер из 19 узлов и 29 переходов, включая обратную связь и общие ветки бюджета/остановки, и большой граф из 79 узлов. Проверяются движение фона и узла, отличие drag от click, точное совпадение SVG с портами в экранных координатах, сохранение состояния между видами, документами и обновлениями прогона, мини-карта, выбор, авторасстановка, масштаб под курсором, touch и клавиатура. Проверяются отдельный worker большой схемы и повтор после ошибки загрузки ELK. Скриншоты сохраняются в `.tmp/ui-smoke/canvas-*.png`.

## Границы решения

Полностью перекрывающиеся карточки могут закрыть порт, и маршрут без пересечения тогда геометрически невозможен. После раздвигания карточек обычная трассировка восстанавливается. На больших графах при активном движении показывается временный маршрут с привязанными концами; окончательный обход препятствий поступает из worker. Worker ELK — дополнительный ресурс примерно 1,6 МБ до HTTP-сжатия и загружается с того же origin.
