# Jira и Confluence

[Документация](README.md) / Интеграции

**Подключайте интеграции после первого локального прогона аналитики.** Для чтения источников нужны адрес и доступ к ним. Клиент Confluence также требует настройку пространства даже для чтения; для создания Jira-задач нужен проект и соответствующие права. Сценарий «Подготовка задачи» требует настроенную Jira ещё до начала генерации.

Примеры ниже описывают поддерживаемую конфигурацию клиентов Orbita. Доступность полей, форм и API на конкретном сервере проверяйте на небольшом тестовом документе или задаче.

## Какие данные запросить у администратора

| Для чего | Что нужно |
| :--- | :--- |
| Чтение Confluence | Базовый URL, токен, email при Basic auth, ключ пространства для v1 или числовой ID для v2, ссылка на страницу с числовым ID |
| Публикация Confluence | Дополнительно при необходимости ID родительской страницы, права создания/обновления |
| Чтение Jira | Базовый URL, токен, email при Basic auth, ключ доступной задачи |
| Создание Jira | Дополнительно ключ проекта, допустимые типы задач, обязательные поля, право создания |
| Корпоративный шлюз | REST-пути, ограничения частоты, сетевой доступ backend к серверу |

Сохраните реквизиты в корневом `.env` и перезапустите backend. Не вставляйте токены в текст задачи.

## Confluence: подключение

### Конфигурация Cloud с публикацией через v2

Замените примерные адреса и значения на свои:

```dotenv
CONFLUENCE_BASE_URL=https://your-company.atlassian.net/wiki
CONFLUENCE_EMAIL=you@example.com
CONFLUENCE_TOKEN=your-confluence-token
CONFLUENCE_API_VERSION=v2
CONFLUENCE_API_PATH=/api/v2/pages
CONFLUENCE_SPACE_ID=123456
CONFLUENCE_PARENT_PAGE_ID=
CONFLUENCE_SEARCH_PATH=/rest/api/content/search
PUBLISH_TARGET=confluence
CONFLUENCE_PUBLISH=1
PUBLISH_REQUIRE_APPROVAL=1
```

Укажите **оба** параметра версии и пути: шаблон `.env.example` явно задаёт путь v1, поэтому одной смены `CONFLUENCE_API_VERSION` недостаточно. Поиск имеет отдельный путь; выбор v2 для публикации не переводит поиск на v2.

### Конфигурация Server / Data Center с v1

```dotenv
CONFLUENCE_BASE_URL=https://confluence.example.com
CONFLUENCE_EMAIL=
CONFLUENCE_TOKEN=your-personal-access-token
CONFLUENCE_API_VERSION=v1
CONFLUENCE_API_PATH=/rest/api/content
CONFLUENCE_SPACE_KEY=DOCS
CONFLUENCE_PARENT_PAGE_ID=
PUBLISH_TARGET=confluence
CONFLUENCE_PUBLISH=1
PUBLISH_REQUIRE_APPROVAL=1
```

Если сервер установлен в подкаталоге, включите его в базовый URL. Код выбирает Basic auth при заполненном `CONFLUENCE_EMAIL` и Bearer при пустом. Для v1 требуется ключ пространства, для v2 — числовой ID.

## Чтение страниц и задач

В «Архитектурной аналитике» можно указать несколько явных источников:

```text
Подготовь проект решения по PAY-123 и странице
https://your-company.atlassian.net/wiki/spaces/DOCS/pages/123456/Refunds.
Прочитай источники, сопоставь ограничения и выдели открытые вопросы.
```

Поддерживаются страницы с числовым page ID в `/pages/123456/...` или `viewpage.action?pageId=123456`, ссылки Jira `/browse/PAY-123` и ключи задач. Домен ссылки должен соответствовать настроенной интеграции. Короткие ссылки `/x/...` и адреса `/display/...` автоматически не разрешаются.

В аналитике автоматически читается до восьми явных внешних источников с ограничением общего контекста. Дальнейший поиск и чтение доступны модели через инструменты. Запрос без готовой ссылки:

```text
Найди в Confluence документацию по возвратам, прочитай подходящие страницы
и подготовь архитектурную аналитику. Приведи источники и укажи пробелы.
```

Поиск и выбор результатов зависят от модели и доступных прав. Проверьте, что ответ действительно содержит прочитанные источники, а не только сообщение о неудачном поиске.

## Публикация в Confluence

1. Запустите сценарий и дождитесь подтверждения публикации.
2. Проверьте пространство, родителя, заголовки и тело каждой страницы.
3. Обратите внимание на действие: создание или обновление найденной страницы.
4. Подтвердите публикацию либо выберите создание черновиков, если оно доступно.
5. Откройте возвращённые ссылки и проверьте результат в Confluence.

Текст преобразуется в Confluence storage format; поддержаны в том числе заголовки, списки, код и Markdown-таблицы. Предпросмотр показывает подготовленное содержимое, но оформление окончательной страницы нужно проверить в самой Confluence.

**Создание черновиков — уже запись в Confluence.** Возвращаются ссылки на редактор, где человек завершает работу. Для существующих страниц создаются отдельные копии. Этот путь предусмотрен для обычных конвейеров; «Обновление документа» сохраняет новую версию через обычное подтверждение.

При совпадении заголовка обычная публикация может обновить существующую страницу. Не используйте один фиксированный `CONFLUENCE_PAGE_TITLE` для независимых задач без проверки назначения. `auto` выбирает Confluence по заполненным настройкам, но не переключается на файлы при ошибке API.

## Jira: подключение

Конфигурация диалекта Cloud:

```dotenv
JIRA_BASE_URL=https://your-company.atlassian.net
JIRA_EMAIL=you@example.com
JIRA_TOKEN=your-jira-token
JIRA_API_PATH=/rest/api/3
JIRA_PROJECT_KEY=PAY
JIRA_CREATE_ISSUES=1
JIRA_CREATE_REQUIRE_APPROVAL=1
JIRA_MAX_ISSUES=50
```

Для Server / Data Center используйте свой адрес, `JIRA_API_PATH=/rest/api/2` и пустой `JIRA_EMAIL`, если работаете с PAT/Bearer. При другой схеме авторизации согласуйте доступ с администратором; встроенной интерактивной OAuth-настройки нет.

`JIRA_PROJECT_KEY` — например, `PAY`, а не числовой ID и не название проекта. Проект можно выбрать в интерфейсе, в том числе перед подтверждением создания.

## Создание задач и ручные формы

Сценарий Jira сначала пишет backlog, затем формирует машинный план. Backend проверяет план и метаданные проекта. Перед созданием пользователь видит карточки именно тех объектов, которые будут отправлены.

| Действие | Результат |
| :--- | :--- |
| `JIRA_CREATE_ISSUES=0` | Документы декомпозиции без создания задач |
| `[подтвердить]` при согласовании Jira | REST-создание; результат содержит ключи и ссылки |
| `[подготовить формы для проверки в Jira]` | Формы/ссылки и данные для ручного создания |
| `[отклонить]` | Создание отклонено; готовые документы не становятся Jira-задачами |

Публикация документов и создание Jira-задач — разные действия и могут запрашивать отдельные подтверждения.

Сопоставление полей поддерживает компонент, сервис, слой, оценку и критерии приёмки, если поля однозначно найдены на экране создания. Если значение нельзя перенести однозначно, оно остаётся в описании с предупреждением. Например, `3 SP` можно интерпретировать как числовую оценку, а `3–5 SP` не превращается автоматически в `4`.

Исполнитель и приоритет не входят в текущий контракт машинной карточки. Поля с нестандартными названиями могут потребовать изменения сопоставления в `jira_fields.py`. Настройки `JIRA_EPIC_TYPE`, `JIRA_DEFAULT_ISSUE_TYPE` и, при необходимости, `JIRA_EPIC_LINK_FIELD` должны соответствовать вашему проекту.

Предзаполнение ручных форм зависит от версии и конфигурации Jira. Наличие параметра в ссылке не гарантирует заполнение поля. В Cloud карточки содержат значения для копирования; проверьте их непосредственно на форме.

## Если интеграция отвечает ошибкой

| Симптом | Что проверить |
| :--- | :--- |
| 401 / 403 | Токен, email, способ авторизации, права на конкретный объект |
| 404 | Базовый адрес, REST-путь, ID страницы/ключ задачи и видимость для этого пользователя |
| Долгое чтение | Паузы `ATLASSIAN_REQUEST_INTERVAL_S` и переопределения для сервисов |
| Частично созданные задачи/страницы | Список результатов каждого объекта; успешно созданное не откатывается |
| Не заполнено отдельное поле Jira | Метаданные экрана создания, допустимые значения и предупреждения карточки |
| Публикация пропущена | `PUBLISH_TARGET`, `CONFLUENCE_PUBLISH`, режим и обязательные реквизиты |

Не начинайте новый полный прогон после частичного создания, не проверив уже существующие объекты: новый тред не является гарантией защиты от дубликатов. Подробности диагностики — [здесь](TROUBLESHOOTING.md).
