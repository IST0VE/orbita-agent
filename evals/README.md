# Оценка качества сценариев

[Документация](../docs/README.md) / Набор задач и базовые показатели

Unit-тесты отвечают на вопрос «код делает то, что написано». Этот набор — на
другой: «получившийся документ годится для работы». Их легко совместить
неправильно, и это обычный способ ухудшить продукт незаметно: конвейер
проходит все проверки, а из документов пропали ссылки на источники, или
противоречие материалов перестало быть замеченным.

Поэтому набор запускается отдельной командой и даёт отдельный отчёт.

```bash
python evals/run.py
```

| Команда | Что делает |
| :--- | :--- |
| `python evals/run.py` | Прогнать набор и сравнить с `baseline.json` |
| `python evals/run.py --case contradiction` | Прогнать один случай; сравнение с базой пропускается |
| `python evals/run.py --json` | Тот же прогон, но машиночитаемо |
| `python evals/run.py --update` | Записать текущий результат как базовый |
| `python evals/run.py --live` | Настоящий провайдер вместо сценария. **Стоит денег** |

Ненулевой код возврата означает ухудшение: либо случай не показал того, что
обязан показать, либо показатели просели относительно базового прогона.

## Что в наборе

Пять случаев, и каждый закрывает свой способ получить плохой документ.

| Случай | Что проверяется |
| :--- | :--- |
| `incomplete-requirements` | Неполные требования отмечены пробелами, а не дописаны догадками |
| `contradiction` | Противоречие двух материалов названо, а не сглажено |
| `unreachable-source` | Недоступный источник не пересказан как прочитанный |
| `publication-failure` | Несостоявшаяся публикация видна в результате и не выглядит успехом |
| `insufficient-metrics` | Вывод об устойчивости не делается по неполным измерениям |

Материалы синтетические и обезличенные: вымышленный сервис, вымышленные ключи
задач, адреса из зарезервированных для документации доменов. Ни одного
реального имени, адреса или ключа в наборе нет.

## Показатели

| Показатель | Что означает | Куда должен двигаться |
| :--- | :--- | :--- |
| `citation_presence` | Доля существенных утверждений с похожей на ссылку строкой; только форма | справочно |
| `source_accuracy` | Доля утверждений, все ссылки которых разрешаются в материалы случая закреплённой версии | вверх |
| `grounded_claims` | Утверждения, совпавшие с разметкой фактов и цитатами из материалов | вверх |
| `unsupported_claims` | Утверждения без подтверждения разметкой и без явного предположения/пробела | вниз |
| `verified_contradictions` | Заложенные противоречия, найденные с обеими ссылками и проверенными фрагментами | вверх |
| `contradictions_mentioned` | Число слов о противоречиях; только форма | справочно |
| `gaps_marked` | Сколько раз пробел данных назван пробелом | вверх |
| `usd`, `seconds` | Стоимость и длительность прогона | не расти |

Показатели считаются по тексту документов и по состоянию прогона, без
модели-судьи: судья стоил бы денег на каждом прогоне и менял бы оценку вместе
со своей версией. Правила распознавания — в [`checks.py`](checks.py); они
проверяемы по материалам. Каждый JSON содержит SHA-256 материалов и разметку
`facts`/`contradictions`: шаблон целого утверждения и точные фрагменты источников.
Несовпадение версии — ошибка набора. Ссылка на отсутствующий файл не считается
валидной; ссылка на существующий файл сама по себе не подтверждает утверждение.

Это ограниченная детерминированная оценка: выделение утверждений эвристическое,
а шаблоны разметки не распознают все возможные перефразировки. В частности,
`publication-failure` намеренно сохраняет три утверждения без опоры — новая
метрика показывает их, хотя ссылки ведут в существующий файл. Их появление
больше не улучшает показатель фактической опоры.

Scripted-стоимость считается по опорному тарифу из `harness.py`. В режиме
`--live` сохраняются выбранные `LLM_*`, ключ провайдера и `PRICE_*`; расход
считается по настроенному тарифу. Настройки внешних публикаций и tracing
изолируются в обоих режимах. Окружение восстанавливается после каждого случая,
в том числе при исключении.

## Модель

По умолчанию модель отвечает заготовленным сценарием и не анализирует prompt.
Этот прогон проверяет прохождение документов через обычный конвейер,
вычисление метрик и поведение публикации. Способность модели обнаружить
противоречие или нехватку данных он не измеряет. Все пять случаев используют
существующий конвейер подготовки документов; это не end-to-end оценка графа НТ.

`--live` отвечает на другой вопрос — как справляется сама модель — и
запускается руками, потому что тратит деньги и даёт разный результат от
прогона к прогону. Он проверяет ожидания случаев, но не сравнивает стоимость
настоящей модели со scripted-тарифом и не может перезаписать scripted baseline.
Результат можно сохранить через `--live --json`.

## Пороги регрессии

Пороги заданы двумя способами, и это разные виды защиты.

- **`expect` в самом случае** — что он обязан показать в любом прогоне.
  Это поломка: противоречие не названо, публикация объявлена успешной.
- **`baseline.json`** — что получилось на базовом прогоне. Отклонение больше
  5% вниз по растущим показателям или рост числа утверждений без опоры —
  это сползание, которое поодиночке незаметно.

Базовые показатели пересчитывают осознанно: `--update` записывает новый файл,
и его изменение видно в истории вместе с тем, что его вызвало. Молча
обновлённый базовый прогон — это выключенная проверка.
