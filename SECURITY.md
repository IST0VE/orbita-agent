# Безопасная эксплуатация

[Обзор проекта](README.md) · [Развёртывание](docs/DEPLOYMENT.md) · [Конфигурация](docs/CONFIGURATION.md)

Orbita читает материалы задач, вызывает платную модель и может записывать страницы Confluence и задачи Jira. Текущая конфигурация предназначена для локального оператора.

## Доступ к серверу

Штатный Compose публикует backend только на `127.0.0.1:2024`. Команды локального запуска также ограничивают backend и Vite loopback-адресом.

`API_ADMIN_TOKEN` обязателен для всего API: `/api/*`, `/assistants`, `/threads`, `/runs`, `/store`, метаданных и других маршрутов. Пустое значение или токен вне диапазона 32–256 ASCII-символов закрывает доступ с HTTP 503; неверный или отсутствующий Bearer возвращает 401. Исключений для localhost, proxy-заголовков и OPTIONS нет. WebSocket закрыт; frontend использует SSE. Токен хранится в `sessionStorage` текущей вкладки и передаётся также при запуске графов.

Сгенерируйте токен командой `python -c "import secrets; print(secrets.token_urlsafe(32))"`, запишите в `.env` или окружение сервера и перезапустите сервер. Токен нельзя изменить через HTTP API. Middleware подключается глобально через `http.app` и `middleware_order: middleware_first`; смена порядка требует повторной проверки защиты всех маршрутов. Ответы API запрещают кеширование, тело каждого запроса ограничено `API_MAX_REQUEST_BYTES`, чтение тела — 30 секундами.

Для Docker Compose также задайте отдельный случайный URL-safe `POSTGRES_PASSWORD` той же командой. Пароля по умолчанию нет. У существующего тома PostgreSQL изменение переменной не меняет пароль роли в базе: согласуйте смену пароля до перезапуска, не удаляя том с данными.

Перед предоставлением общего доступа нужны TLS, ограничения частоты запросов и индивидуальная аутентификация перед API. Общий административный токен не разделяет пользователей и их данные. Штатный frontend работает через один origin (Vite proxy); прямой cross-origin доступ и его CORS-политика требуют отдельной настройки.

## Ключи и материалы

- Храните ключи в корневом `.env` или окружении процесса. `.env` исключён из Git; `.env.example` должен содержать только шаблонные значения.
- Не помещайте ключи в `VITE_*`: значения сборки frontend доступны браузеру.
- Подключайте к `AGENT_INPUT_DIR` только предназначенные для работы материалы. Текст выбранных файлов передаётся модели.
- Для аналитики и подготовки задачи инструменты могут читать соседние файлы выбранной папки. Разделяйте независимые материалы по папкам.
- Маскирование при публикации не означает маскирования до отправки модели. Подготовьте допустимый к обработке вход заранее.

Настройки UI возвращают секреты маской и не раскрывают их значение. Это не делает весь сервер безопасным для анонимного доступа: он также читает документы и запускает обработку.

Через настройки можно сохранять только документированные переменные приложения; произвольные имена и управление токеном запрещены. Неизвестные переменные при чтении маскируются. Подстановка `${...}` в сохраняемых значениях запрещена. На POSIX новый `.env` создаётся с правами `0600`; Windows требует корректных ACL каталога. Файлы `.env*`, `*.env`, `*.pem` и `*.key` не читаются через инструменты материалов. Остальные входные документы всё равно должны быть заранее проверены на секреты.

## Внешние действия

Оставляйте `PUBLISH_REQUIRE_APPROVAL=1` и `JIRA_CREATE_REQUIRE_APPROVAL=1` для интерактивной работы. Перед согласием проверяйте назначение, заголовки, содержимое и действие создания/обновления.

Создание черновика Confluence тоже записывает объект во внешнюю систему. Подготовка ручной формы Jira сама не доказывает создание задачи. При частичной ошибке уже выполненные действия не откатываются автоматически.

HTTP для удалённых Jira/Confluence по умолчанию запрещён; локальные адреса имеют отдельное исключение. Параметры `*_ALLOW_INSECURE_HTTP` предназначены для явно настроенного исключения.

Jira/Confluence не следуют HTTP-перенаправлениям, включая 307/308 с телом документа: настройте конечный адрес API. Переопределения адреса LLM требуют HTTPS (HTTP разрешён только для loopback), без credentials, query и fragment.

## Маскирование и бюджет

Публикуемый текст проходит встроенное маскирование распространённых секретов. Дополнительные шаблоны задаются через `CONFLUENCE_MASK_PATTERNS`, разделённые `||`; строка замены — `CONFLUENCE_MASK_REPLACEMENT`. Автоматическое распознавание не гарантирует удаления всех чувствительных данных.

`BUDGET_USD_PER_THREAD` проверяет накопленную расчётную стоимость до следующего вызова. Он требует корректного тарифа и не гарантирует точного потолка итогового списания. Ограничения учётной записи провайдера задаются вне Orbita.

## Эксплуатационные проверки

Тесты блокируют реальные подключения и DNS-запросы; на Windows допускается только внутренняя socketpair для asyncio. Личные `.env` и трассировка отключены в тестах. Ruff проверяет опасное исполнение кода, десериализацию, shell и отключение TLS. CI также проверяет зависимости через pip-audit и npm audit. Эти проверки не доказывают отсутствие всех уязвимостей или секретов произвольного формата.

Проверьте доступность сервера только по ожидаемому адресу, папки и тома, сохранность `.env` и результата после перезапуска. Проверки кода — в [руководстве разработчика](docs/DEVELOPMENT.md).

Не публикуйте полный вывод `docker compose config`: в нём могут оказаться подставленные секреты. История тредов, результаты и резервные копии также могут содержать переданные материалы.

## Сообщение об уязвимости

Передайте владельцу репозитория по приватному каналу минимальное воспроизведение, затронутую версию и влияние. Не публикуйте ключи, `.env`, корпоративные документы или рабочий exploit в открытом issue. Для обычных ошибок используйте [памятку диагностики](docs/TROUBLESHOOTING.md).
